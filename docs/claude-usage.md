# Claude の活用（開発の進め方）

ハッカソンの審査「Claude の活用」のための説明です。数字は、このリポジトリの git と実物から数えたものだけを書いています（測っていない数字は書きません）。

## アプリの中での Claude

5つの場面（読む・訳す・つなぐ・聞く・Telegram の通訳）で Claude API（claude-opus-5-5・構造化出力）を呼び、答えをそのまま見せずにコードで原本や計算と照らし合わせてから出します。
訳すときは日付を Claude に渡さず（元の予定からコードがその言葉の形で入れる）、一般的な説明は「原本に書いてあること」と別の欄に返させて札を付けます。通訳の執事は、書類がサーバーに無いので、返信先のお知らせの文だけを根拠にします。
詳しくは README の「Claude の使い方」と [docs/decisions.md](decisions.md)（作りながら決めたこと）に。

## 開発の分担（Claude Code のセッションを3つに分けた）

| 係 | すること | 成果物 |
|---|---|---|
| アプリ本体 | 画面・データの形・Claude の呼び出し・確認スクリプト | このリポジトリ |
| 見本と正解とテスト | 架空の書類と正解 JSON（96件）・本番を自動で試す検査・動画の台本 | 見本は `public/samples/`・正解は `src/data/photoSamples.json` に取り込み |
| 全体を見る係 | 何を作るか・順番・判断しない線を決め、2つの係の報告を読んで指示する | 非公開の作業メモ |

3つは別々の Claude Code のセッションで、非公開の作業メモ用リポジトリ（STATUS・決めたこと・報告）だけを共有しました。
本体の係は、セッションをまたぐたびにそのメモから再開します（クラウドのセッションは前の会話を覚えていないため）。

## 正解と照らし合わせる（機能より先に、測れる形）

- 見本の書類には1件ずつ正解 JSON（何の書類か・誰の・いつの分か・予定・問い合わせ先・読めなかった所・家全体か）が付いています。見本はすべて架空で、期間中に新しく作ったものです
- `scripts/eval-extraction.mts` の1コマンドで、見本をアプリと同じ指示・同じ返す形で Claude に読ませ、項目ごとに正解と突き合わせて正解率の表と料金の見積もりを [docs/eval/latest.md](eval/latest.md) に書き出します。採点の仕組みはこの1つに決め（審査員が見る所）、見本と正解の係が持つ採点は照らし合わせ用です
- 日付の規則や「読めるか」の判断は人が見ます。スクリプトは数えるだけです

## 毎回、本番で確かめる

- `scripts/smoke.mjs`（プロジェクトのスキル `demo-check`）は、スマホ幅・時計固定で「架空の家族で始める → トップ → 予定 → 書類 → 聞く・頼む → 見本をまとめて渡す → まとめて確定 → 聞きたいことに答える → 誰ので分ける → 崩れた紙 → メールの束ね → 大事な番号」を通す18項目の確認です
- 区切りごとに、手元で通してから main に入れ、本番（Vercel）に反映したら本番でも同じ18項目を通します
- 見本と正解の係は、本番を自分で開いて見本を全部渡し、書類の画面を正解 JSON と見比べる検査（prod-check）を回し、食い違いを報告に書きます。本体の係はそれを読んで直し、また本番で確かめる往復です（11/2 夜の例: 受付中の期間が「いちばん近い締切」に出る・同じ日で語が重なるだけの別の用事が束なる・まとめて確定のあとに残る件数の文・10以上の数え方、の4件）

## Claude Code の機能の使い方

- Skills: Claude API を呼ぶコードを書く前に `claude-api` スキルで現行の書き方（構造化出力・effort・fallbacks・料金）を確かめる。デモの流れの確認はプロジェクトのスキル `demo-check` に
- MCP: 非公開の作業メモ用リポジトリをセッションに付けて再開する（add_repo）。環境のことで詰まったときは現在のドキュメントを読む（read_documentation）
- 並行のセッション: 本体と、見本・正解・テストの係を別々のセッションで並走させ、ファイルが重ならない場所に置く
- セッションの中の Playwright: スマホ幅の画面の通し確認・画面の画像の撮り直し（`scripts/shots.mjs`・`scripts/shots-final.mjs`）・Claude API の返事を差し替えて、間違った答え（ありえない ID・違う日付・判断の言い回し）をコードが外すかの確認
- tsx: 画面を操作しなくても、家のデータの関数（束ねる・覚えたことの当てはめ・大事な番号の当たり方）を直接動かして確かめる

## 数字（git と実物から）

- 確認スクリプトの項目: 18（授業参観と勤務の書類のつなぎ・同居の家族だけ・話したことを覚える、を含む）
- 見本: 85件（写真 61・メールの本文 24）。正解つき。見本と正解の係が作ったものは全部で 96 件（残りはアプリの架空の家族に最初から入っている書類と、同じ形の見本）
- 想定している書類の範囲: 40 分野（見本あり 29・設計上の対象 5・ハッカソンのあとに 6）。一緒に住んでいる家族の書類に絞り、離れて暮らす家族の6分野はあとで広げる範囲にしています
- Claude API を呼ぶ入口: 3（/api/extract・/api/connect・/api/ask）
- 作りながら決めたことの記録: docs/decisions.md
