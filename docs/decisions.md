# 作りながら決めたこと

CULALOG を作る途中で迷ったところと、そのときに選んだこと・理由の記録です。
会期中に新しく決めたものだけを、決めた順に近い形でまとめています。

## 守る線

- **判断をしない。** 保険・医療・法律について「補償されます」「解約して大丈夫です」とは言いません。
  執事が出すのは「どの書類のどこに何と書いてあるか」と「問い合わせ先」までです。
  「うちの場合は保険が使える可能性があります」のような当てはめも言いません。最終的な確認は原本と窓口でお願いしています。
- **判断を書く欄を作らない。** Claude に返させる形（構造化出力）そのものに、「対象になります」などの結論を書く場所がありません。
  文の中に判断の言い回しが混じった答えは、コードが出さずに止めます。
- **日付の計算はコード。** 期限の逆算（例: わが家のきまり「休みの申請は1週間前まで」）・何日前かの計算・くり返す期限の次の回は、すべてコードで計算します。
  Claude の答えの中の日付も、コードで書類の日付と照らし合わせます。
- **採用するのは利用者。** 執事の気づき（例: 「授業参観、見に行きますか？」→「行く（休みの申請の締切を予定に）」）は、利用者がボタンを押すまで予定に入りません。
- **原本と見比べて確定するまで、根拠に使わない。** 読み取った下書きは、利用者が原本と見比べて確定したものだけを、ひとこと・予定・聞くの根拠にします。
- **仮のものは仮と出す。** Claude を呼べないとき（キーが無い・回数の上限）に使う仮の結果・仮のひとこと・仮の気づき・仮の答えは、画面に必ず「仮」と出します。
- **気づきは言い切らない。** 「〜かもしれません」という提案までにしています。

## 言葉の壁をつなぐ

- **訳すだけではなく、つなぐ。** 書類を訳すだけのアプリは既にあります。CULALOG が持っているのは家族の書類と予定なので、訳した文には書いていない「その日は妻も夫も仕事」「夫のシフト表では休みの希望は前の週の金曜まで」に気づけます。
  同じ日の気づき（子どもの行事 × 大人の出勤日）は、どの日がぶつかるかをコードが日付から見つけ、その候補を Claude に渡して、書類の行から文を書いてもらいます。
  コードは、文の中の日付（行事の日・勤務の書類に書いてある申し出の期限）・名前（子ども・仕事の大人）・「家族で決める」が候補と合うか、「有給」などの休み方の言葉が無いかを照らし合わせ、合わなければコードの文に戻します。日付を Claude に計算させないため、と、候補に無い「同じ日」を Claude が作らないためです。誰が行くかは決めません（執事は決めない・家族で決める）。
- **同じ日の気づきは「その日は仕事」だけを中心にし、休み方を決めつけない。** 「有給を取るなら」は、その家の休み方を執事が決めつけています（有給が残っていなければ欠勤・計画休暇・シフトの交代になり、二人とも行かない答えもあります）。
  また、ほかのことでは「いつまでに」をそこまで言わないのに、わが家のきまりにたまたまある有給の申請だけ期限を押し出すのは不自然です。
  そこで期限は、勤務の書類そのものに書いてあるとき（シフト表の「休みの希望は前の週の金曜まで」など）だけ、その書類の名前つきで添え、わが家のきまりからは作りません。
- **候補日から選ぶ行事は、候補日ごとにカードを出さず1枚にまとめる。** 個別懇談会の「候補日①〜④」を日ごとに出すと、同じ話のカードが何枚も並びます。
  1枚に「候補日は○日〜○日の4日」「このうち○日・○日は△△さんがお仕事のよう」「○日は勤務カレンダーでは休日」「□□さんの12月の勤務は、まだ預かっている書類にない」と並べ、どの日を希望するかは家族が決めます。
  行事の書類に希望の提出の締切があれば添えます。提出を済ませたら（または日が決まった別のお知らせが届いたら）このカードは出しません。日ごとの組み合わせが多く照らし合わせが難しいので、この文はキーがあってもコードの文です。
  トップに出すのは1枚だけ（日が決まった子どもの行事を先に）で、ほかは「ほか○件」から予定の画面へ。
- **町内会・自治会の清掃・当番も、同じ日の気づきの対象。** 平日の当番・清掃は、働く世代は仕事で出られないことが多いためです。日にちと時間が書いてある回覧に限り、期間だけの当番（「12月中」）は出しません。
- **同じ日の気づきは、保護者が行く行事だけ。** 平日の行事は大人の出勤日とほぼ全部ぶつかるので、行事の数だけ並べても役に立ちません。
  出すのは、名前に 参観・懇談・面談・保護者会・説明会・引き渡し があり、時間まで分かっている（案内プリントが来ている）もの。年間行事予定や学年だよりの日付だけの段階では出しません（案内プリントを待つ声かけが別にあります）。
  運動会・発表会のような家族みんなで行く行事は「誰が行くか」の話ではないので出しません。
  大人の側は、勤務先の書類に書いてあるその日の出勤（シフト表の「出勤（日勤 …）」・勤務カレンダーの土曜出勤など）と、題名が「勤務カレンダー」の書類がある人の平日（その書類に休日・休暇の予定がある日は除く）です。
  **父も母も仕事の日**なら二人とも書きます（片方だけなら、その人だけ）。「授業参観と母の出勤日が同じ日」だけだと、母の予定だけを見ているように読めて不自然なためです。原本は、行事・それぞれの勤務の書類の3つを並べます。
  最初は保育園の運動会（土曜）と土曜出勤の重なりを山場にしていましたが、運動会は両親とも行くのがふつうで「1人が行く・誰が担当」がリアルでないため、平日の授業参観に替えました。
- **読みたい言葉は、国籍ではなく本人が選ぶ。** 設定で家族ごとに選びます（日本語・ベトナム語・やさしい日本語）。「やさしい日本語」も一つの読みたい言葉として並べます。
- **配偶者でも自動では共有しない。** 書類ごとに「家族と共有」を選びます。共有した人の言葉で伝えられ、担当の候補になります。
  何を家族に見せるかは預けた人が選ぶ、という線を守るためです（本人あての書類まで自動で渡さない）。
- **訳は3つに分ける。** ①原本に書いてあること（原本の場所つき。押すと原本の行が光る）②理解を助ける一般的な説明（「授業参観とは」「学級懇談会とは」「土曜保育とは」）③原本からは分からないので確かめること。
  ②は「この学校・園の決まりではない」と札を付けて①と混ぜません。説明を足さないと伝わらず、足すとこの園の決まりに見える、の両方を避けるためです。
- **日付は訳さない。** 日付は Claude に渡さず、元の予定からコードがその言葉の形（Thứ Bảy, 21/11/2026）で入れます。訳の中で日付が変わる事故を無くすためです。
- **送る前に全部見せる。** 「家族に伝える」は、どこへ・何人が読むか・全文を画面で確かめてから送ります。グループに送ると全員が読むので、グループの人の読みたい言葉を全部入れます。
  書類の写真・ほかの書類・大事な番号は入れません。原本の引用は紙の順に添え、執事はそれを根拠に返信に答えます。
- **担当はボタンで、家族の名前ごと。** 「タオがやる / Thảo sẽ lo」のように家族の名前のボタンにし、誰が押したかではなくどのボタンを押したかで決まります。
  夫が代わりに押しても「タオが担当」にでき、Telegram の人と家族を結びつける情報をサーバーに置かずに済みます。
- **通訳は全部訳すモード。** グループの会話をすべて受け取って訳します（プライバシーモードを切る）。会話の文は保存せず、`/pause` で止められます。
  README に「会話をすべて受け取り、訳すために Claude へ送る。保存はしない」と書きます。
- **サーバーに置くのは最小限。** Firestore に置くのは、グループの人ごとの読みたい言葉と表示名・つなぐ合言葉の指紋・近い予定の日付と件数・通知した日だけ。書類の中身・予定の名前・会話の文は置きません。
  毎朝の通知も「近い予定が○件あります」と件数だけで、予定の名前は送りません。
- **公開に書く作者の話の範囲。** 「作者の家は国際結婚で、妻はベトナム出身。夫婦とも相手の言葉は片言」までは書きます。家族の名前・顔・学校名・本物の書類・本物の Telegram の画面は出しません。

## 書類の扱い

- **書類のデータは端末の中に置く。** 読み取った内容・写真・予定・覚えたことは、ブラウザの中（IndexedDB）にだけ保存します。
  Claude に頼むときだけ、必要な部分をサーバー経由で Claude API に送り、サーバーには残しません。
- **送るときは番号を伏せる。** 聞く・つなぐで書類の中身を送るときは、証券番号などの番号を伏せ、電話番号は送りません。
  写真の中の番号は伏せられないため、そのことは README に正直に書いています。
- **大事な番号は端末の中で答える。** 年金・雇用保険・印鑑登録・証券番号のような、めったに見ないのに手続きで急に聞かれる番号は、
  「○○の番号は？」「○○持ってる？」と聞かれたら Claude に送らずに、確定した書類からコードで探して答えます。
  番号は伏せて表示し、「見る」を押したときだけ見せます。聞いた記録にも番号そのものは残しません。
- **年度の取り違えを防ぐ。** 書類ごとに「何年度のものか・いつまで有効か」を持たせ、同じ種類の新しい書類（改訂版など）が来たら、
  古い方を「前のもの」にするかを利用者に聞きます。前のものは、ひとこと・予定・聞くの根拠に使いません。
- **メールは貼り付けで受け取る。** メールで届く書類は、本文の貼り付け・スクショ・PDF で渡せます。
  メールのアカウントに自動でつなぐ機能は作っていません（「これから」は README に）。

## メールで届く書類

家に届くメールのうち、期日を覚えておく価値があるものはごく一部で、残りは宣伝や利用の通知です。そのため、次のようにしています。

- **予定と「知っておくだけ」を分ける。** 利用者が動かないと困るもの（申し込み・提出・支払い・止めるなら申し出）と、
  自動で引き落とされる・自動で継続するなど、知っておくだけのものを分けます。知っておくだけのものは、予定のひとことや期限の知らせには出さず、
  すべての予定・書類の画面で見られるだけにしています。
- **同じ予定は束ねる。** 1つの期日について、初回のお知らせ・督促・前日の通知と何通も届くことがあります。
  日付が同じで名前の言葉が重なる予定は、予定では1件にまとめ、「同じ予定のお知らせがほかに○通」と添えます。
- **済んだお知らせで閉じる（決めるのは利用者）。** 「納付完了」「退会完了」などのお知らせを確定したら、つながりそうな予定について
  「済みましたか？」と聞きたいことに並べます。勝手に済んだにはしません。
- **訂正は「済んだ」と区別する。** 「お支払い期限の訂正」「日程変更」のように前のお知らせの予定が置き換わるメールは、
  済んだのではないので、「この書類で訂正されましたか？」と聞き、前の予定だけを消して訂正後の予定を残します（入金の確認とは混ぜません）。
- **束ねた予定は、済んだも一緒。** 束ねた何通かのうち、どれか1つを済んだにすれば（利用者が押しても、済んだお知らせから答えても）、束ね全体を予定で知らせなくなります。
  取り消すときも一緒に戻します。同じ束ねの中の予定について、同じ質問を2回はしません。
- **リンク先にしか無いことは、推測で埋めない。** 金額や満了日が本文に無く、リンクの先にしか無いときは、
  「リンク先にしか書いてありません。開いて確かめてください」と出します。アプリはリンクを開きません。
- **日付が何種類も並ぶときは、別々の予定にする。** 保険の満期日・自動継続の日・止める場合の申し出の締切・決済の予定日などを、
  原本の書き方のまま別の予定として読み、取り違えないようにしています。

## 撮って、まとめて渡すだけ

- **人はいっぺんに投げ、執事はコツコツ読む。** 何枚でも受け取り箱に入れ、画面を開いているあいだに1枚ずつ読みます。
  閉じても、次に開いたときに続きから読みます。回数の上限に当たったら、時間をおいて自動で続けます。
- **分からないことは、あとでまとめて聞く。** 読みながら分からなかったこと（誰の書類か など）は「聞きたいこと」に並べ、
  空いた時間に選択肢で答えてもらいます。答えは「覚えたこと」として残し、同じ種類の書類では二度聞きません。
  覚えたことは Claude には送らず、読み取りのあとにコードで当てはめます。
- **原本だけでは決められないことは、埋めずに外す。** 写真の下が切れて振替日が写っていない・「別紙参照」なのに別紙が無い・「12月5日（日）」と書いてあるのに12月5日は土曜、
  のようなときは推測で埋めず、「読めなかった所」として理由を添えてまとめて確定から外し、原本で確かめてもらいます。
  二つの書類で同じ行事の日付が食い違うときは、どちらかを選ばず両方を予定に出して、違いに気づけるようにします。
- **同じものに気づく。** 同じファイルは二度読みません。同じ書類の写真違い（種類が同じで、予定の名前と日付が全部同じ）は
  「同じ書類ですか？」と聞きます。改訂版や日付違いは、写真違いと取り違えないよう「前のものにしますか？」の方へ回します。
- **登録したときにはもう過ぎていた締切は騒がない。** 古いプリントをあとから撮って渡したとき、間に合わない締切で予定が埋まらないよう、
  トップ・予定では期限切れとして知らせず、すべての予定の画面にだけ「登録したときには、もう過ぎていました」と添えて残します。
  登録したあとに過ぎたものは、今まで通り知らせます。
- **知らせたら終わりにしない。** 「済んだ」を押していない締切は、1週間前・3日前・前日にもう一度ひとことに出します。

## Claude とコードの分担

- **候補を作るのはコード、何を言うか選ぶのは Claude。** 予定のひとことは、コードが期日の逆算・来ていない書類・聞きたいことから候補を作り、
  Claude が数件を選んで言い回しを付けます。締切が3日以内・過ぎたのに選ばれなかったものは、コードが必ず別に出します（取りこぼし防止）。
- **Claude の答えは、ID と言い回しで返させる。** 予定・書類・きまりの ID だけを返させ、日付・原本の場所はコードが持っているものを出します。
  実在しない ID や、書類と違う日付が入った答えは出しません。
- **呼ぶ回数を絞る。** つなぐ＋ひとことは、書類・きまりが変わったときと日付が変わったときだけ呼び、結果は端末に保存します。
- **執事の名前は Claude に送らない。** 名前は利用者が自由に付けられますが、口調はキャラの種類だけで決め、名前は画面でコードが差し込みます。
  名前に変な文を入れられても、答えの中身は変わりません。

## 中身は正確に、温度は柔らかく

- 執事の名前・口調・あいさつは、続けて使ってもらうための工夫です。キャラを変えても、期日・引用・原本の場所・判断しない線・迫った期限の警告は同じです。
- 公開の説明では「AI に感情がある」とは言わず、「人が続けて使えるように温度を持たせた」と書いています。
- 作っていない機能（端末内の暗号化など）は、README でも「ある」とは書きません。

## 話したことを覚える

- **書類が無い予定も、話すだけで覚える。** 年に1回しか解約できないサブスクのように、書類が手元に無くても締切があるものは、
  執事に話すと予定の案を出します。質問なのか覚えてほしいのかは Claude が分け（聞くの返す形に「種類」を足した）、
  日付が正しい日付か・話した月と合っているかはコードが確かめ、いつから知らせるか（解約できる時期なら1か月前など。話した中に「3日前」などがあればその日数）もコードが計算します。
- **登録するかは利用者が決める。** 案は確定ボタンを押すまで予定に入りません。名前と日付は確定の前に直せます。書類の確定と同じ線です。
- **原本は話した言葉。** 書類が無いので、原本の場所は「利用者が話したこと（日時）」とし、話した文をそのまま原本の文字として残します。
  誰のことか話に出てこなければ、話した利用者のものにします。
- **キーが無いときは仮の案。** 「覚えて」「その前に教えて」などの決まった言い回しと「（来年の）○月（○日）」だけをコードで読み、画面に「仮」と出します。
- **声で話せる。** 聞く画面のマイクのボタンで話すと、入力欄に文字が入ります。声を文字にするのはブラウザーの音声認識（Web Speech API）で、
  Chrome は Google、Safari は Apple のサーバーを使うことがあります。声は CULALOG のサーバーにも Claude にも送りません。
  このことは、初めてマイクを押したときと設定の画面に、そのまま書いています。対応していないブラウザーではボタンを出さず、キーボードの音声入力を案内します。
  執事の答えの読み上げ（ブラウザーの音声合成）は設定でオン・オフでき、この端末だけの設定です。
- **頼みごとは、アプリの中で画面を移っても止めない。** 調べる係をどの画面にも付いている1か所に置きました。
  スマホで裏に回って（ほかのアプリ・ホーム画面・画面を消す）通信が止まったときは、「つながらなかった」の仮の答えで埋めず、戻ったときに続きから調べます。
  書類のデータを預からない設計なので、アプリを閉じている間にサーバーで調べ続けることはしていません。

## 誰のものか

- **扱うのは、一緒に住んでいる家族の書類。** デモの家族は同居の4人（翔太・タオ・蓮・結衣）だけにしました。離れて暮らす親の書類まで見ると、
  親の情報を預かる説明が重くなり、介護について判断しない線も守りにくくなるためです。
  同居の家族が当事者の書類（翔太の介護休業の承認、タオが付き添う予定）は、その人の書類として扱います。
  親あての書類（年金の通知・介護保険の被保険者証・利用票など）は、記入例と同じ「この家の書類ではない」扱いで、誰の欄にも出さず予定にもしません。
  読み取りの指示にも同じ線を書いています。離れて暮らす家族への広げ方は、ハッカソンのあとに考えます。
- **デモの「つなぐ」の例は、授業参観と勤務の書類。** 運動会は一般に土日で、仕事とぶつかるのは土日も働く人だけです。授業参観は必ず平日なので、
  働く親はみんな休みを取ります。デモの家族の「土日も勤務がある」という前提は外し、
  「まだ届いていない案内プリント」も授業参観のものにしました（運動会は予定として残っています）。
- **授業参観は学年だより・案内プリントから拾い、行くかを聞く。** 年間行事予定には授業参観の日まで書いていないことが多いので、
  デモの家族では学年だよりに日付があり、時間・教室は案内プリントで知らせる形にしました。執事は「見に行きますか？」と聞き、
  「行く」を押したときだけ、わが家のきまり（休みの申請）の締切を予定に入れます。行くと決めつけて予定を増やさないためです。
  学年だよりと案内プリントの両方に同じ日の授業参観があっても、聞くのは1回です。

- **トップから全部に行けて、どこからでも1回で戻れる。** 開くとトップ（メニュー）。家族の丸いアイコン・いちばん近い締切1件・6つの入口（予定・書類・家族ごと・大事な番号・聞く・わが家のきまり）。
  どの画面にも左上に「‹ トップ」、下のタブの左端も「トップ」です。
- **誰のか書類から分からないものは、勝手に誰かに入れない。** 読み取りで誰のことか言い切れないときは、宛名の人に寄せず「誰のか分からない」のまま執事が聞きます。
  住まい・光熱・通信・家財の保険・家の車・町内会などは「家全体」として、ひとりのページには出しません（その人のことでもあるときだけ、その人にも出します）。
  二人以上に関係する書類（現況届と就労証明書など）は、その全員に出します。この家の書類ではないもの（記入例・見本）は誰にも出しません。

## 見せ方

- **見せ方を変えても、中身は変えない。** 白い背景・丸いカード・種類の挿絵・右の大きな「あと何日」・小さな「原本」の札で、どの画面も同じ調子にしています。
  文言・日付の計算・判断しない線は、見せ方を変える前と同じです。
- **挿絵は線なし・丸い形を塗るだけ・1つの絵に色は3つまで**（オレンジ・紺・黄が軸）。空っぽのとき・読んでいる最中には執事の絵。
- **家族の丸は、名前の1文字より顔で。** 名前だけだと誰が誰か伝わりにくいので、キャラクター（背景・肌・髪の3色）から選べるようにしました。
  自分の写真も使えますが、写真は端末の中にだけ置き、サーバーにも Claude にも送りません（家のデータとは分けて置き、保存を重くしません）。
- **押せる所は指で押せる大きさ**（戻る・タブ・切り替えは 44px）。動きを減らす設定（prefers-reduced-motion）に従い、iPhone の下の余白（safe-area）を空けます。

## デモ

- **前提知識なしで試せる入口。** 最初の画面の「架空の家族で試す」と、渡す画面の「写真の見本をまとめて渡す」で、すぐに流れを試せます。
- **デモの家族・会社・書類はすべて架空。** 会期中にこのリポジトリのために作り、名前は架空と分かるもの、電話番号は 000- で始まるものにしています。
- **デモの日付は開いた日が基準。** いつ開いても同じ流れを試せます（写真の見本だけは撮影日を基準にした画像のため、日付が動きません）。
